Leeyes Unicode Hack
===================

Leeyes 2.6.1（Win32版）のファイルアクセスと表示を補完するフックDLLおよび
インジェクタです。

Leeyes本体は古いANSI/CP932前提のAPIを多く使用するため、Unicode文字や長いパスを
含むファイルを一覧表示できない、画像を開けない、書庫内の画像を読めないといった
問題が起きることがあります。本プロジェクトは、必要な場合だけUnicode APIや
合成パスへ切り替えて、LeeyesとSusieプラグインから実際のファイルへ到達できる
ようにします。


対応状況
--------

現在の実装では、次のようなパスを対象にしています。

- CP932で表現できない文字を含むパス
- CP932のbest-fit変換で別の文字に見えてしまうパス
- 絵文字、`·`、その他のUnicode記号を含むパス
- Windowsの通常のパス長を超える長いパス
- Unicodeパス上に置かれたフォルダ、画像、ZIP書庫

ファイル一覧、サムネイル、画像表示、書庫内画像の読み出しに加え、取得できた
Unicode名をLeeyesの表示へ戻す補正も行います。特に、`·`（U+00B7）と `・`
（U+30FB）のようにANSI変換後の表記が似るケースも、実在する項目が一つに
特定できる場合は補完します。

対応する主な経路は以下です。

- 画像Susieプラグイン
  - `iftwebp.spi`
  - `IFJPEGX.SPI`
  - `IFPNG.SPI`
  - `ifavif.spi`
  - `WIC_Loader.spi`
  - `axffmpeg.spi`
- 書庫Susieプラグイン
  - `arc.spi`
  - `ax7z.spi`
  - `axpdf.spi`
  - `axffmpeg.spi`
- `arc.spi` でUnicodeパス上のZIPを扱うための補完
  - ZIPの無圧縮エントリ
  - ZIPのDeflateエントリ
- Leeyesの多重起動
- WSLのネットワークプロバイダ `p9np.dll` による既知のクラッシュ回避

通常のASCII/CP932パスは、プラグインの既存処理を優先します。Unicodeパスの
解決やフォールバックは、破損したパス、長いパス、または通常のアクセスに失敗した
場合に限って使用します。


インストールと使用方法
------------------------

Leeyes本体とSusieプラグインを用意し、次のファイルをLeeyes本体と同じフォルダへ
配置します。

- `LeeyesW.exe`
- `inject_dll.dll`
- `inject_dll.ini`

`LeeyesW.exe` はDLLを読み込んでから、同じフォルダの `Leeyes.exe` を起動する
ランチャーです。通常の `Leeyes.exe` ではなく、必ず `LeeyesW.exe` を起動して
ください。

`inject_dll.ini` の `[Archive]` に、使用する書庫プラグインを設定できます。
初期値は以下です。

```ini
[Archive]
FileName=ax7z.spi
```

各設定の意味は、同梱の `inject_dll.ini` 内のコメントを確認してください。

`[Option]` の主な設定は以下です。

```ini
[Option]
HookFindFirstFile=1
HookCreateMutex=1
HookSetWindowText=1
HookTextDrawing=1
```

`HookFindFirstFile=1` はUnicode名や長いパスを含むファイル一覧の補完、
`HookCreateMutex=1` はLeeyesの多重起動、`HookSetWindowText=1` はウィンドウタイトルや
リスト・コンボボックスなどへ設定される文字列の補正を有効にします。
`HookTextDrawing=1` はGDIの文字描画時に、ANSI変換で失われたファイル名を補正します。

`HookTextDrawing=0` にすると、文字描画フックだけを無効にできます。表示補正が
不要な環境では、通常の文字描画経路への介入をなくせます。設定項目を省略した
場合は `1` として扱います。

大量のファイル追加・削除・移動に対する一覧更新の集約は、次の設定で有効になります。

```ini
[InternalHook]
FileMoveBatch=1
FileMoveBatchThreshold=32
```

`FileMoveBatch=1` は、Leeyesが蓄積した変更キューを処理するとき、
`FileMoveBatchThreshold` 件以上なら1件ずつ一覧全体を更新せず、キューをすべて
消費した後に通常の一覧再同期を1回だけ行います。固定時間の待機や通知の破棄は
行いません。単発変更や閾値未満の変更は従来経路のまま処理します。設定を省略した
場合の初期値は、それぞれ `1` と `32` です。

制限事項
--------

- すべてのSusieプラグイン、書庫形式、Windows APIを置き換えるものではありません。
  使用するプラグインが独自の方法で物理パスを要求する場合は、補完できないことが
  あります。
- 異なるUnicode名が同じANSI表記へ変換され、実在する候補を一つに決められない
  場合は、誤ったファイルを開かないため補完を中止します。
- 8.3短縮名を利用できない場合は、プロセス内の合成パス、または
  `%TEMP%\LeeyesUnicodeHack` 以下のエイリアスへフォールバックすることが
  あります。TEMPへの書き込みやエイリアス作成が制限される環境では、プラグインの
  読み込みに失敗する場合があります。
- 本体の内部データがANSI/CP932形式で保持されている操作には、LeeyesW側で補完
  できる範囲に限界があります。本棚への登録、削除、名前変更、プロパティ表示など
  は、使用する処理経路によって利用できない場合があります。
- ZIPの特殊な形式、暗号化、巨大な書庫などは、標準の `arc.spi` 経路を含めて
  対応範囲外になる場合があります。
- 32bitのWin32版を対象としています。
- 一覧更新の集約はLeeyes 2.6.1の内部処理を対象にしています。必要な関数の命令列を
  起動時に検証できない改造版では、安全のため内部フックを有効にしません。
- Leeyes本体、Susieプラグイン、7z.dllなどの第三者バイナリは同梱していません。
  それぞれの配布元から入手してください。


性能について
------------

Release版では、通常の画像一覧・読み込みで余計なファイルログを出力しません。通常の
パスは元のANSI処理を直接呼び、Unicode補完用の探索や
エイリアス作成を行いません。

一方、Unicode名の復元、長いパスの解決、ANSI変換の衝突判定などは、必要なときに
だけ追加処理が発生します。特殊なエッジケースをすべて常時検査して通常経路を
遅くする設計にはしていません。そのため、対応範囲を広げる変更は、通常の一覧や
画像表示へのコストと引き換えにならないかを確認してから行います。

文字描画フックも、損失変換を示す `?` がない通常の文字列は表示名マップを検索せず、
元の描画APIへ直接渡します。


ソースコードとライセンス
--------------------------

ソースコードはVisual Studio用のソリューションに含まれています。各ファイルと
同梱ライブラリには、それぞれの著作権表示とライセンスが適用されます。第三者製
プラグインやLeeyes本体の再配布については、各配布元の条件に従ってください。
